# Чистота репозитория

Канонические исходники проверки принадлежат Base. Продукты хранят одинаковые
автономные копии: достаточно Python 3.10+ и Git, без SDK/UI repin и runtime.

```sh
python3 -B scripts/check_repository_hygiene.py --index
python3 -B scripts/check_repository_hygiene.py --ref HEAD
python3 -B scripts/tests/test_repository_hygiene.py
```

Проверяется полный Git index или точный commit. Код 0 — нарушений нет, 1 —
запрещённые tracked paths, 2 — невозможно проверить полный snapshot. Результат
содержит только пути и причины, без содержимого файлов и Git stderr.
Untracked caches сохраняются; конфликтный index отклоняется.

## Что хранится в Git

Исходники, актуальные инструкции, API/схемы/generated clients, необходимые assets,
fixtures и эталоны регрессионных тестов. Исторический провальный пример остаётся,
если он нужен действующей проверке. Дата и расширение сами по себе не делают файл мусором.

Workspace-recovery пакеты не возвращаются в актуальные ветки. Старые версии
уже доступны в Git-истории: перенос в новый archive или backup не нужен.
Кэши, bytecode, compiler metadata, HTML coverage, Playwright/test-results и сырые
логи в docs не являются исходниками. Обычные fixture logs в tests и поставляемые
assets, включая plugin dist, разрешены.

Результаты каждого прогона не превращаются в постоянный отчёт или новый план.
Использовать существующие CI artifacts с ограниченным retention и компактное
описание результата в PR. Скриншоты хранить в Git только для действующей
документации, дизайна или автоматического эталона. Удалённый ресурс требует
исправления ссылок; зеркало Base обновляется штатным synchronizer после владельца.

## Проверка и hooks

Локальные hooks проверяют index и конкретные отправляемые SHA. Перед их установкой
проверить существующий core.hooksPath; shared worktrees используют общий Git config.
Не перезаписывать чужие hooks. Серверный короткий PR/push workflow проверяет
точный candidate commit: локальные hooks можно обойти.

```sh
git config --local core.hooksPath .githooks
```

Checker проверяет состав, а не семантическую полезность документа или безопасность
секретов. Не добавлять исключения ради зелёного gate: нужный fixture должен иметь
явное назначение. Не удалять реальные данные, runtime inputs или уникальные
неопубликованные изменения. Миграции, лицензии, frozen maintenance-контракты,
SDK/UI pins и история Git не переписываются.
