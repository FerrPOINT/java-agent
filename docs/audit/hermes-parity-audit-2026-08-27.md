## Verified parity in the audited seams

- Both runtimes contain LENGTH stitching, truncated-tool-call recovery, empty-response budget/backoff, dropped-tool-call recovery, interruptible retry, finish-reason routing and post-tool compression.
- Duplicate tool-call IDs are uniquified before assistant persistence in both normal and streaming loops.
- Sync execution fails closed after assistant or tool-result persistence failure and has approval handling for sequential and parallel batches.
- Context overflow, provider quota/billing distinction and malformed tool-history classification are substantially aligned in `ErrorClassifier`.
- Telegram draft finalisation uses rich persistent delivery first, scrubs think markers before silence detection, and handles heartbeat state without repeated standalone heartbeat messages.
- Cron `context_from` output chaining, model threshold floors and deterministic compression fallback are present from the 2026-08-26 ports.

## Intentional differences / not findings

- PostgreSQL/JPA, UUIDs, virtual threads and Spring services replace Hermes SQLite/files/asyncio; these are architectural choices, not parity failures.
- Desktop/TUI, non-Telegram platform adapters, installer/UI, provider-specific integrations and plugin-only features are outside the Java agent's declared scope unless requested separately.
- No Hermes source was modified during this audit.

## Required test matrix before closure

1. Tool aliases: raw `id`, `call_id`, `response_item_id`, composite identifiers; test live turn, persisted/reloaded history, compaction and replay.
2. Streaming tool gate: invalid name, malformed JSON, duplicate call, approval timeout/deny, persistence failure, interrupt before/after tool.
3. Cron: >4,000-char Unicode output, ordered chunks, retry/idempotent delivery and `bot-chat` target.
4. Prompt: session-specific disabled `memory`, `skills`, `todo`, `web_search`; assert prompt never names an unavailable tool.
5. Review cancellation: a new foreground turn/reset interrupts a pending review and blocks stale write effects.
6. Empty OpenRouter cache retry, escaped-error cap, disabled-compression overflow and repeat-result stubbing.
7. Full regression: `./gradlew test --max-workers=1`, `./gradlew slowTest --max-workers=1`, then a local noop smoke/E2E. Deployment is deliberately excluded pending explicit authorization.
