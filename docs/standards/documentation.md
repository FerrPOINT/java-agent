# Стандарт документации и тестов

Действует для всего кода в `backend/`, `telegram-bot/`, `cli/`. Краткая версия — в `AGENTS.md` § Documentation standard; этот файл — полный текст с примерами.

## Принцип

Документация отвечает на вопрос «почему и для чего», а не пересказывает код. Тесты доказывают поведение, а не форму. Половина недоработок в проекте — следствие того, что контракт был в голове автора, а не в коде.

## Javadoc

### Class-level — обязателен, если класс ≥ 50 строк

Одна-три строки: что инкапсулирует и зачем существует, если это не очевидно из имени и пакета. Запрещено пересказывать имя.

```java
// ПЛОХО — вода, имя уже это говорит
/** Service for managing memory operations. */
public class MemoryService { ... }

// ХОРОШО
/**
 * Релевантные факты из memory-стора, инжектируемые в volatile tier system prompt.
 * Формат блока byte-совместим с эталонным (см. ReviewSummary для фоновых записей).
 */
```

Классы < 50 строк (records, DTO, исключения, конфиг- holder) — javadoc не требуется.

### Методы — только для контрактов, которые кто-то другой вызывает

Обязателен javadoc на:
- public/protected методах **port-интерфейсов** (`core/ports`) и их адаптеров;
- public методах сервисов, вызываемых из других пакетов;
- всех `@AgentTool` (description — это контракт для LLM, см. ниже);
- REST-контроллерах: `@Operation(summary=…)` вместо javadoc; javadoc на классе — какие ресурсы он объединяет.

Не требуется: getters/setters, `@Override`, private/package-private, конструкторы Lombok, простые записи.

Метод-джавадок отвечает на: что делает (одной строкой), какие побочные эффекты/гарантии неочевидны, какие значения недопустимы, что возвращает в граничном случае. Не описывай очевидное.

### Запрещённые формулировки (линтер DOC002)

- «responsible for», «provides functionality», «utility class», «helper class», «management of», «This method is used to», «Конфигурация настроек», «Различные утилиты».
- Javadoc, дословно повторяющий имя класса/метода (`/** Memory service */`).
- Перечисление параметров, которое дублирует код без добавления ограничений.

### Комментарии в коде

- Только WHY: неочевидное решение, обход чужого бага, паритетное правило со ссылкой на источник (`// Hermes parity: turn_finalizer.py:790` — хороший пример).
- Комментарий, пересказывающий код — удалить.
- Каждая миграция Flyway: одна строка-комментарий WHY перед классом.

## Описание тулов (@AgentTool)

`description` — это контракт для модели: когда звать, что вернёт, когда упадёт. Хороший образец — `TerminalTool` (PTY/буферизация в описании). Плохой — «Executes the operation». Смена описания тula = смена поведения модели; правь осознанно.

## Стандарт тестов

### Что обязано сопровождать код

1. **Новая логика** → unit-тесты на поведение, включая граничный случай и негативный путь.
2. **Багфикс** → regression-тест, доказано красный до фикса (см. `ResponseRecoveryParityTest` — образец).
3. **Контракт SSE/error** → всякая refuse-ветка backend получает lane в бот-классификаторе (`StreamingOrchestrator.toUserFriendlyError`) и тест на неё в `telegram-bot`. Бэкенд-ошибка без бот-lane = пользователь видит «Temporary issue» (инцидент 2026-09-19).
4. **Сравнение enum/строк из провайдера** → всегда `equalsIgnoreCase`; тест обязан прогонять ОБА регистра («LENGTH»/«length») — sync и streaming пути нормализуют по-разному.
5. **Wiring** → сеттер/метод с нулём вызовов = мёртвый код (класс багов «выглядит портированным»). Новый seam получает тест, доказывающий вызов.
6. **Живые тулы** → unit-моков недостаточно; периодический smoke через `/api/ops/doctor` (per-tool статусы) + живой вызов хотя бы раз при смене провайдера.

### Coverage-ratchet

- `docs/standards/coverage-baseline.json` фиксирует текущие LINE-% по модулям.
- PR не может опустить модуль ниже baseline; рост тестов → `--update-baseline` коммитом «chore: raise docs/coverage baseline».
- Долг по legacy-коду гасится пакетами из bottom-списка (см. baseline), не разом.

### Чего не делаем

- Change-detector тесты (снапшот счётчиков/каталогов, «assert len == N»).
- Тесты, читающие исходники тестируемого кода.
- Моки там, где дешёв real-path тест (MapStruct `Mappers.getMapper`, H2 для репо-маппинга).
- Тесты ради процента без инварианта.

## Линтер и CI

```bash
python3 scripts/check_docs_standard.py            # проверка + сравнение с baseline
python3 scripts/check_docs_standard.py --update-baseline  # опустить baseline до текущего (только при росте тестов — ручной аудит)
python3 -m unittest scripts.tests.test_check_docs_standard  # тесты линтера
```

CI (job `docs`): линтер падает, если нарушений больше baseline. Ratchet только вниз — baseline поднимается осознанно вместе с покрытием.
